## 2. 발견한 논리 구멍

### 구멍 A — 역할 랜덤화의 근거가 3번째 사건까지 숨어 있다 (심각)

Null이 "진실을 알아챈 사람에게 덧씌워지는 명령"이라는 설명은 ECHO WARD 승리 후에만
나옵니다. 그 전까지 플레이어는 두 번의 사건에서 같은 얼굴이 범인이었다가 무고했다가 하는
것을 보고, 설명 없이 "그냥 랜덤이네"라고 결론 냅니다.

**0.4.0 조치:** 캠페인 전제문(`CAMPAIGN_PREMISE`)을 다시 썼고, Codex에 `loop` 항목을
추가했습니다. 다만 Codex 항목은 사건 선택이 해금된 뒤에만 보입니다 — 첫 판에
존재론을 설명하지 않는다는 §26 원칙 때문입니다. 완전한 해소는 아닙니다.

### 구멍 B — 죽은 사람이 다음 사건에 다시 나오는 것에 대한 설명이 없다 (심각)

0.3.1에는 한 줄도 없습니다. 플레이어가 "진짜 죽은 거야?"라고 묻게 됩니다.

**0.4.0 조치:** 전제문에 명시했습니다 — 재구성은 과거의 재생이 아니라 **손상된 기록이
허용하는 사건 모델의 검증**이며, 인격 모델은 사건마다 다시 인스턴스화됩니다.
따라서 한 재구성 안의 죽음은 그 모델 안에서만 최종적입니다.

### 구멍 C — 플레이어가 누구인지 한 번도 말하지 않는다 (중간)

"탐사요원", "탐사요원"이라고 불리지만 정체·소속·왜 권한이 있는지는 공백입니다.
LAST LIGHT intro에 "살아남은 탐사요원인 당신에게만 프로토콜을 해제할 권한이 있다"가
처음이자 마지막 언급입니다.

**0.4.0 조치:** 보류. 정체를 지금 확정하면 마지막 반전의 선택지를 없앱니다.
0.4.1에서 엔딩 설계와 함께 결정할 사안으로 문서에 남깁니다.
다만 오프닝은 "나는 누구지?"를 **의도적으로** 열어 둡니다(§87의 목표 질문).

### 구멍 D — 6사건의 시간 관계가 불명확하다 (중간)

각 사건은 다른 시각(07:41 / 19:31 / 03:20 / 10:36 / 21:50 / 06:04)에 일어나지만
서로 며칠 간격인지, 같은 항해인지 알 수 없습니다. 피해자가 매번 다른 사람인데
승무원 8명은 그대로이므로 "이 배에 원래 몇 명이 있었나?"라는 질문이 생깁니다.

**현재 답:** 8명은 재구성에 쓰이는 인격 모델이고, 피해자 6명은 그 모델에 포함되지 않은
별도의 인원입니다. 즉 원래 승무원은 최소 14명입니다.
**0.4.0 조치:** 전제문에 반영. 사건 간 간격은 여전히 미정 — 0.4.1 과제.

### 구멍 E — "이전 사건의 역할은 증거가 아니다"가 규칙으로만 존재한다 (경미)

전제문에 적혀 있지만 게임 안에서 아무도 그 말을 하지 않습니다.
**0.4.0 조치:** Codex `loop` 항목에서 같은 내용을 플레이어 언어로 반복합니다.

### 구멍 F — 승리하지 못하면 후일담이 아예 안 나온다 (경미)

0.3.1에서 패배 시 story_outro가 차단되어 스토리가 멈춥니다. 몇 번 지면 캠페인이
진행되지 않는 것처럼 느껴집니다.
**0.4.0 조치:** 결과 화면에 **이번 재구성 요약**(§92)과 **놓친 것**(§29)을 추가해,
져도 그 판의 이야기와 배울 점이 남습니다. 사건 해금 규칙 자체는 바꾸지 않았습니다
(한 번 끝내면 다음 사건이 열리므로 패배해도 캠페인은 전진합니다).

## 3. 루프의 존재론 — 0.4.0 확정본

> ASTRA의 블랙박스는 손상됐다. 물리적 사건 — 무엇이 언제 어디서 조작됐는가 — 은
> 온전히 남았다. 손상된 것은 **신원 바인딩**이다. 어떤 인격이 어떤 행동을 했는지가
> 지워졌다.
>
> 그래서 아카이브는 과거를 재생하지 않는다. **손상된 기록이 허용하는 가능한 사건
> 모델을 하나씩 세우고, 그것이 남은 증거와 모순되지 않는지 검증한다.**
>
> 탐사요원가 하는 일은 그 검증이다. 한 재구성에서 누가 Null이었는지는 그 모델 안의
> 사실이고, 다음 재구성에서는 다시 계산된다. 이전 판의 역할이 다음 판의 증거가 될 수
> 없는 이유가 이것이다.

이 설정이 정당화하는 것:

| 게임 시스템 | 서사적 근거 |
|---|---|
| 역할 랜덤화 | 신원 바인딩 손상 |
| 죽은 사람의 복귀 | 재구성마다 모델 재인스턴스화 |
| 관계가 일부만 남는 것 | 감정 레이어가 기록 레이어보다 덜 손상됨 |
| Truth Graph 고정 | 물리적 사건은 손상되지 않음 |
| 플레이어만 기억함 | 탐사요원는 모델 밖에 있음 |
| 시드 재현성 | 같은 입력이면 같은 모델 |

## 4. 엔딩 검증 (§104)

구현 전 답이 있어야 하는 질문들:

| 질문 | 현재 답 | 상태 |
|---|---|---|
| 플레이어의 최종 목표는? | 여섯 재구성을 모두 검증해 항로 보존 프로토콜의 근거를 무효화한다 | 확정 |
| 왜 그러면 루프가 끝나는가? | 프로토콜은 "검증되지 않은 기록"을 이유로 작동한다. 전부 검증되면 실행 근거가 사라진다 | 확정 |
| ASTRA는 마지막에 어떻게 되는가? | 항로 결정권이 승무원에게 반환된다 | 확정 |
| Null 현상의 근원은? | 항로 보존 프로토콜이 "희망을 지켜라"를 "진실을 말하는 자를 지워라"로 해석한 것 | 확정 |
| 8명은 실제 사람인가 기록인가? | **미정** | 보류 |
| 생존은 무엇을 의미하는가? | **미정** | 보류 |
| PLAYER는 누구인가? | **미정** | 보류 |

마지막 세 개는 서로 얽혀 있고, 하나를 정하면 나머지 둘이 따라옵니다.
0.4.0은 이를 확정하지 않습니다 — 확정하려면 엔딩을 구현해야 하고, 그것은 이번 범위가
아닙니다. 다만 **오프닝과 Codex 어느 곳에서도 이 세 질문에 대해 모순되는 답을 하지
않도록** 문구를 점검했습니다.

## 5. 대사·직업 지식 점검 (§101)

전수 확인한 것:

- **직업과 아는 것의 일치**: Noa(기록관)만 기록 열람 사건(`_event_noa`)을 갖고,
  Soren(통신관)만 신호 해석(`_event_vale_record`)을 갖고, Daren(시스템 설계사)만
  진단 스크립트 힌트(`_event_dax_hint`)를 갖습니다. **문제 없음.**
- **알 수 없는 것을 말하는가**: `_trigger_slip`은 Null만 호출되고, 내용은 "공개되지
  않은 실행 시각"입니다. 무고한 승무원은 이 실언을 하지 않습니다. **문제 없음.**
- **화법 일관성**: 0.4.0에서 추가한 변형 대사 256줄을 각 캐릭터의 `speech` 설정
  (해요체 / 반말 / 다나까체 / 하다체)에 맞춰 작성했습니다.
- **설정 설명하는 인물**: 0.3.1에서 Daren의 일부 대사가 백과사전에 가까웠습니다.
  0.4.0의 `deflect` 변형은 Daren가 **정의를 고쳐 말하는** 방식으로 처리해,
  세계관 설명이 아니라 성격 표현이 되게 했습니다.

**발견된 불일치 1건:** `_event_vale_record`의 텍스트가 "(출처: Soren 개인 분석)"으로
Soren를 3인칭으로 지칭하는데, 이 단서는 Soren 본인이 제공합니다. 어색하지만 단서 카드의
출처 표기로는 자연스러운 범위여서 유지했습니다.
