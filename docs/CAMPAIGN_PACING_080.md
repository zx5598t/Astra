# ASTRA 0.8.0 — Campaign Pacing Map (개발용)

플레이어에게 보이는 문서가 아니다. 캠페인을 “한 편의 SF 미스터리”로 읽기 위한 리듬 설계표다.
스토리 사실은 `docs/STORY_LEDGER_080.md`가 기준이고, 이 표는 그 위에 **리듬(무엇을 번갈아 경험하는가)** 을 얹는다.

원칙
- 플레이타임은 Day 수나 대사량으로 늘리지 않는다. 사회추리 · 스토리 · 인물 · 공간 · 짧은 상호작용 · 결과를 번갈아 쓴다.
- 20~35분마다 한 번은 리듬이 바뀐다(토론 → 걷기/조작 → 토론).
- 인터루드는 “미니게임”이 아니라 **스토리의 한 장면**이다. 실패해도 막히지 않고, 끝나면 반드시 새 정보·관계·질문 하나가 남는다.
- 인터루드 실력은 추리의 증명이 아니다. 손이 빠르다고 Null을 알 수 없다(맥락·신뢰·빠른 해결만).
- 초상화 = 감정/대화, 도트 캐릭터 = 공간/행동. 두 표현을 섞지 않는다.

|---|---|---|---|

**재사용 모티프**(§18·§19): C(신호 추적)는 Stage 4에서 평범한 잡음 정렬 → Stage 11/13에서 “동시에 존재하는 두 시각”
→ “존재해서는 안 되는 출처”로 변한다. A(갑판)는 Stage 10에서 같은 공간인데 문 하나·표지 하나가 다르다.

## 4. 실패와 재시도의 리듬 (§25–31)

- 탐사요원 사망 = 그 Stage의 재구성 실패(즉시 결과). 다음 Day로 넘어가지 않는다.
- 실패 장면 → 공개적으로 이해 가능한 사후 설명(“Null이 당신을 노린 이유”) → 기록 확인 / 재구성 재시도 / 타이틀.
- 재시도 = 같은 Stage의 **새 재구성**(새 시드·새 Null 가능·새 Day Packet). 불러오기 = 같은 재구성(시드·Packet·Null 동일).
- 죽음의 잔향: 재시도 첫 아침, 탐사요원만 기억하는 “마지막 밤 전에 들은 말” 한 줄. 정답 힌트는 없다.
- Stage 9 이후의 실패는 “균열” 장면으로 조금 더 무겁게 연출한다(같은 날짜가 두 번 지나간다, 시계가 몇 초 늦다).
- 완료한 Stage는 체크포인트. 캠페인 전체 영구 사망은 기본값이 아니다.

## 5. Residual Echo (감정 잔향) 규칙

- 지난 Stage의 사건이 **감정**으로만 남는다: 밤에 쓰러짐(fell), 탐사요원이 잘못 보낸 무고한 사람(sent_by_you),
  Aegis가 지켜 낸 사람(shielded), 탐사요원이 변호한 사람(defended).
- 다음 Stage 첫 아침, 최대 1회. 두 Stage 연속으로는 드물게. PART II가 열리는 Stage 5에서는 확실히 1회.
- 구체적 기억·역할·정답은 절대 남기지 않는다. 대사는 `AstraStageStory.ECHO_LINES`(8명 × 4종, 인물 말투).
- 목적: 애착, 연속성, “정말 기억이 완전히 사라지는가?”라는 큰 질문의 작은 증거.

## 6. 엔딩 (계획)

Stage 13 해결 뒤 20~40분의 최종 악장: 최종 판단 → 함선 세트피스 → 강한 답 하나 확인 → 인물 콜백(캠페인 기록 기반,
짧게) → 마지막 선택 → 에필로그(TRUST / FRACTURE / DISCOVERY 중 캠페인 기록으로 톤 결정) → 마지막 이미지와 ASTRA 메시지 →
크레딧 → **심층 재구성(DEEP RECONSTRUCTION) 해금** 연출.
