# ASTRA 0.4.2 설계

## 이야기와 규칙

플레이어는 ASTRA의 탐사요원이다. 현재 목표를 따라 이동·조사·대화하고, 동료의 기억과 남은 기록을 비교한다. Null은 현재 사건의 위험한 조작에 관련된 규칙상 역할이다. 인물의 영구적 악역 정체성이나 루프의 최종 원인을 뜻하지 않는다.

| 호환 챕터 ID | 이번 발견 | 깨어 있는 동료 |
|---|---|---|
| CALIBRATION | 잠금 해제 기록과 첫 반복 | 미라·준·다렌·노아 |
| DEAD_AIR | 서로 다른 목적지의 원본 문서 | 4명 |
| GLASS_GARDEN | 순찰 기록과 배치 기록의 불일치 | 세나 합류, 5명 |
| ECHO_WARD | 수면 중 소렌의 음성 | 소렌 합류, 6명 |
| SILENT_ORBIT | 19년 전 도착 완료 기록 | 루칸 합류, 7명 |
| RED_SHIFT | 출항보다 오래된 목적지 시료 | 마렌 합류, 8명 |
| LAST_LIGHT | 서로 다른 사본을 함께 보존 | 8명, 원인은 미해결 |

첫 각성은 EXPLORE → RESULT(CONTINUE)로 진행한다. 이후에는 EXPLORE → BRIEFING → INVESTIGATION → INTERROGATION → MEETING → VOTE → NIGHT를 사용한다. 일찍 끝나거나 실패해도 발견한 이야기와 다음 장은 이어진다. 4~6인 사건은 조작 1개, 7~8인 사건은 조작 2개다. 개별 흔적은 후보를 주고 두 흔적의 교차나 동선 모순으로 실행자를 좁힌다.

## 단일 상태 모델

`game_session.gd`가 탐색과 추리 상태를 모두 소유한다. UI는 공개 메서드만 호출한다. `voyage_content.gd`에는 챕터·장소·장면·반응 데이터를 둔다. 기존 `case_catalog.gd`의 원시 템플릿은 옛 저장의 물리적 토폴로지 복원용으로 보존하고, 새 사건을 만들 때는 새 서사로 덮어쓴다.

`voyage`에는 장소, 방문, 만난 사람, 사실, 조사 지점, 현재 대사와 선택, 최근 장면, 목적지 기억, 과거 관계, 동행, 물품, 지연 반응, 장기 관계가 들어간다. 메타에는 완료한 새 챕터 목록, 직전 목적지/관계, 감정 잔향, 장기 신뢰를 저장한다. 사건의 의심·긴장·유죄 역할은 새 사건마다 분리해서 만든다.

신뢰와 잔향은 다음 회차의 초기 신뢰와 장면 조건에 반영한다. 대화 선택은 현재 신뢰도 바꾼다. 공유·숨기기·도움·변호는 뒤의 이동에서 후속 행동으로 돌아온다. 휴대 기록기로 보관한 사본은 기존 야간 백업 판정을 사용한다. 물품을 잘못된 장소에서 쓰거나 두 번 쓰면 상태가 바뀌지 않는다.

## 대화 선택

화자, 현재 위치, 동행, 장면 태그, 관계, 루프 수, 직전 회차의 지목, 실제 상실, 발견 여부를 확인한다. 최근 6개에 없는 장면을 우선하며, 후보가 작아도 진행이 막히지 않도록 제한된 fallback을 쓴다. 일상·업무·관찰을 더 자주 선택한다. 개인사·비밀·잔향은 5행동 이후, 장면당 회차 내 한 번이다. 주요 발견은 확률 추첨과 분리하며 6행동 뒤에도 놓쳤다면 전달한다.

170개 탐색 장면은 일상·업무·친밀·거리감·갈등·의심·사건 후·위험·안도·잔향·기억·개인사·밤·각성·상실·NPC 대화·사과·요청·변호·비밀·관찰을 포함한다. 추리 장면의 거짓말·증거 반응과 NPC 관계 사건은 별도 기존 풀에서 새 말투로 제공한다. 전체 장면이 매번 나오지 않는다.

## 저장과 버전

진행 저장 v3는 기존 v1/v2 필드를 읽고 `voyage`를 추가한다. 오래된 진행은 저장된 명단·진실·단서·RNG와 당시 사건 토폴로지를 유지한다. 이전 대사의 문장 기록은 역사적 기록으로 보존한다. 새로 생성되는 이름과 초상은 현재 카탈로그(art050)를 사용한다. 숫자 관계 값은 ConfigFile 소수 직렬화 오차 범위에서 비교하며 RNG·선택·문장은 정확히 비교한다.

기존 내부 ID는 유지한다. 사용자가 직접 만든 기록이나 기존 슬롯을 자동 삭제하지 않는다. 0.4 완료 점수는 보존하고 새 항해 챕터 목록을 따로 두어 새 시작이 중간 각성부터 뛰어넘지 않게 한다.
