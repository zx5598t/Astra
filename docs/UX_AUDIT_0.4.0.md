# UX / 인지부하 감사 — ASTRA 0.3.1 → 0.4.0

0.3.1을 **처음 실행하는 사람**의 관점으로 다시 플레이하고 측정한 기록입니다.
수치는 실제 코드와 화면에서 센 것이며, 추정치는 그렇게 표시했습니다.

---

## 1. 첫 1분에 이해해야 하는 정보

**0.3.1 — 11개**

타이틀에서 바로 노출되던 것:

| 항목 | 화면 |
|---|---|
| 계속하기 / 첫 항해 시작 / 사건 선택 | 타이틀 |
| 조사 방식 3종(분석관·공감관·감사관) | 아카이브 |
| 사건 6종 + 잠김 상태 | 아카이브 |
| 관측자 등급, 통찰 점수 | 아카이브 |
| 사건별 최고 등급·챌린지 배지 | 아카이브 |
| "Null", "재구성", "블랙박스", "프로토콜" | 첫 모달 |
| 8명 전원 이름 | 게임 진입 즉시 |

첫 모달이 다음 문장으로 시작했습니다:
"ASTRA는 흔적과 알리바이를 맞춰 숨은 Null 두 명을 찾아내는 추리 게임입니다."
— 이 한 문장에 처음 보는 명사가 3개입니다.

**0.4.0 — 3개**

오프닝이 주장하는 것은 세 가지뿐입니다.
① 배에 큰 일이 있었다 ② 기록이 온전하지 않다 ③ 누군가 숨기고 있다.
"Null"이라는 단어는 오프닝에 나오지 않습니다. 첫 사건의 브리핑에서 처음 등장합니다.

## 4. 첫 회의의 총 발언 수

실측(DEAD_AIR, 20 시드 평균):

| | 0.3.1 | 0.4.0 |
|---|---|---|
| 첫 회의 발언 수 | 14–20 | 9–14 |
| 표시 방식 | 0.55초 타이머 자동 | 클릭/Space 1건씩 |
| 한 발언이 화면에 머무는 시간 | 0.55초 고정 | 플레이어가 결정 |
| CALIBRATION 첫 회의 | — | 7–9 |

0.55초는 한국어 한 문장을 읽기에 부족합니다. 8명이 말하면 4.4초 만에 끝났습니다.
`tests/social_tests.gd`가 발언 수 상한과 "같은 사람이 연달아 말하지 않음"을 검사합니다.

## 5. 아무것도 모르는 사용자가 처음 누르는 버튼

**0.3.1**: 타이틀의 "첫 항해 시작" → 사건 브리핑 → 화면 아래 큰 파란 버튼.
여기까지는 괜찮았습니다. 문제는 그 다음 조사 화면입니다. 화면에 동시에 있는 인터랙티브 요소가
**장소 4 + 조사 지점 3 + 임무 1 + 노트 + 메뉴 + 다음 = 11개**였고, 무엇이 "지금 할 일"인지
시각적으로 구분되지 않았습니다.

**0.4.0**: 화면 상단에 항상 한 줄이 있습니다.

> 지금 할 일 — 통신실을 먼저 살펴보세요.

그리고 조사 화면의 주 행동은 하나(조사 지점)입니다. 임무는 해금 전까지 없습니다.

## 6. 현재 목표가 항상 보이는가

0.3.1: **아니오.** `phase_hint()`가 있었지만 설정에서 끌 수 있었고, 규칙 설명과
행동 지시가 한 문장에 섞여 있었습니다.
예: "장소와 조사 지점을 고르세요. 기록 시각을 사건 시간대와 대조하는 것이 중요합니다."
— 앞은 지시, 뒤는 규칙입니다.

0.4.0: **예.** 목표 줄(지시)과 힌트 줄(규칙)을 분리했고, 목표 줄은 끌 수 없습니다.

## 7. 잘못 눌러 막히는 구간

0.3.1에서 확인된 것:

- 튜토리얼 중 조사 지점을 누르기 전에는 "다음" 버튼이 비활성인데, **왜 비활성인지는
  버튼 텍스트로만 알려줬습니다**("조사 지점을 먼저 살펴보세요"). 툴팁도 없었습니다.
- 개인 면담이 뜨면 다른 모든 심문이 잠깁니다. 이유가 화면에 없었습니다.

0.4.0:
- 목표 줄이 "왜 지금 못 넘어가는지"를 항상 말합니다.
- 개인 면담은 CALIBRATION에서 아예 발생하지 않습니다.
- `test_tutorial_cannot_dead_end`가 20개 시드로 "일부러 못 하는 플레이"를 돌려
  모든 시드가 RESULT까지 도달하는지 검사합니다.

## 10. 중요 정보와 잡정보의 시각적 구분

0.3.1의 문제는 색이 아니라 **크기**였습니다. 본문 13·14·15·16px이 한 화면에 섞여 있었고,
"사건 핵심 단서 제목"과 "이동은 자유롭게" 같은 안내가 거의 같은 크기였습니다.

0.4.0은 타입 스케일을 5단계로 고정했습니다(`AstraUI.T_*`).
가장 작은 크기는 14px이며 그 아래는 사용하지 않습니다.
1366×768에서 12px 한국어는 읽기 어렵고, 0.3.1의 캡션 대부분이 12px였습니다.

## 남은 문제

- **조사 화면의 조사 지점 배치가 고정 좌표**입니다(0.21/0.52/0.80). 배경 아트와 무관하게
  세 점이 같은 자리에 찍히므로 "현장을 본다"는 느낌이 약합니다. 0.4.1 과제.
- **AP를 시간("30분 경과")으로 표현하는 것과 숫자 AP가 섞여 있습니다.** 하나로 통일해야 합니다.
- 회의 카드가 길어지면 스크롤이 생기고, 이전 발언을 다시 보려면 위로 올려야 합니다.
  "전체 기록" 버튼을 넣었지만 근본 해결은 아닙니다.
